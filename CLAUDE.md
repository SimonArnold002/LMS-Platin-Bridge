## What this is

A bespoke bridge presenting the **Platin Stereo Hub HT** to Lyrion as an ordinary
player, over UPnP AVTransport / RenderingControl, with the Hub's own control port
(TCP 50006) for power and input. **It is for one MODEL - every Platin Hub on the network gets its own player since 0.2.7 (Simon, 2026-11-01: "we need to account for multiple hubs if someone has them", `WHICH HUB IS WHICH`) - and will not be
generalised.**

**Since 0.2.0 it carries no audio stage.** It advertises the formats the Hub plays
(from the Hub's own Sink list), LMS's transcode table turns each track into one of
them - SqueezeDSP's rules when SqueezeDSP is on for this player - and the bytes go
to the Hub as they came out. DSP, upsampling and ReplayGain are SqueezeDSP's.

**Why it exists alongside the UPnP Bridge.** The bridge's power-off wake was fixed
upstream (#98, row 38) and Simon runs his own build of it, but this player can do
what the bridge cannot for this one device: switch it on and off from LMS's power
button, follow its own power and input changes, tell a power-off from a stop, see
the Hub fetch the next track (the TrackURI-lag hand-over, `THE TRACK LAG IS THE
BRIDGE` in SqueezeDSP's ledger), and pass SqueezeDSP's stream through untouched.

**Only one of the two may drive the Hub.** While this plugin is in use the Hub must
be disabled in the UPnP Bridge, or two LMS players (both named after the Hub,
"Lounge") will drive one renderer.

## Architecture

```
LMS source --(LMS transcode table / SqueezeDSP)--> flc | wav | native --> /platin/<player>/<seq>.<ext> --> Hub
                                                                       (each track's opening kept for a re-GET)
LMS power button --audio_outputs_enable--> Control.pm --TCP 50006--> Hub MCU (read, then toggle)
Hub remote / app / standby --02 0e / 02 02 pushes--> Control.pm --> LMS power on (no play) / off, pause on input change
```

| Piece | Job |
|---|---|
| Player.pm | advertises formats (`myFormats`), arms each next track with SetNextAVTransportURI, passes the stream through with the replay buffer, reads UPnP state (1 s poll), maps power/input/stop as below |
| Stream.pm | the endpoint: what each GET is owed (live, replay from 0, a `Range`, 410/416/503), socket take-over |
| Control.pm | TCP 50006: frames, read-then-toggle power, source list and selection, pushes, a 30 s poll as dead-peer detection |
| Format.pm | the format table: order, mime, extension, which Sink entries prove a format; the header repair (frame finder, STREAMINFO / RIFF makers) and the readout of what a stream's first bytes say |

### Power, input and the remote - the contract

| Event | What happens |
|---|---|
| LMS power OFF | LMS pauses/stops (PauseOff), then `audio_outputs_enable(0)`: the Hub is switched off **only if it is on Streaming** |
| LMS power ON | after 1.5 s the Hub is switched on - **unless playback started in that time**, because the Hub switches itself on when the stream arrives and a toggle would cross that |
| LMS restart | nothing is toggled (state unknown at player creation); LMS adopts the Hub's state from its first 50006 report |
| Hub switched off (remote, app, standby) | LMS powers off (`power 0`); a paused track is marked lost, so the next play restarts it at its position (`time N`) |
| Hub switched on | LMS powers on WITHOUT resuming (`power 1 1`) |
| Hub leaves Streaming while LMS plays | LMS pauses (`pause 1`), track marked lost as above |
| Hub's play / pause | followed (UPnP PLAYING / PAUSED_PLAYBACK), pause only once our track has started. LMS's pause is not sent back to a Hub already paused; a PLAYING resumes LMS only after the Hub had paused, and without reloading the track |
| Hub's stop, Hub ON | LMS stops |
| last track ends | `playerStopped` when LMS streams nothing; a held next track is started |
| volume on the remote | followed (GetVolume each second) |
| next / prev / mute | **not mapped yet** - `REMOTE BUTTONS NOT YET CAPTURED` |
| play on this player, Hub on another input | the Hub is put on Streaming first |

## The Hub's control port, TCP 50006 - facts used

Frame: `[length 2 BE][checksum][class][opcode][data]`, length counts everything after
itself, checksum = sum(class..data) & 0xFF (unchecked by the firmware). Class 02:

| | query | report (pushed on every change, twice for a network change) | command |
|---|---|---|---|
| power | `00 03 0f 02 0d` | `02 0e 00|01` | `00 04 11 02 0f 00` - a TOGGLE |
| source | `00 03 03 02 01` | `02 02 {"src":[{"ix","name","sts"},...]}` | `02 03 <ix>`; Streaming is ix 9 on this Hub |

Sources on Simon's Hub (2026-10-25): Line, eARC, OPT1, OPT2, OPT3, COAX, USBDISC,
PC/MAC, Bluetooth, Streaming. Source of the protocol: drsound/aiolibresync
(docs/protocol-system-control.md, commands.md); the HT specifics from its issue #2.
"Power" is not mains: the Hub answers on both ports while off; off is a stop; on
restores nothing.

## Design rules - non-negotiable, these ARE the bug being fixed

1. **Nothing the Hub reports may ever start LMS playing.** A report may pause, stop,
   power off, or power on WITHOUT resuming. The one exception is the Hub's own play
   button on a track LMS had paused - and only once the Hub had itself paused.
2. **Unreachable means no opinion.** A Hub that stops answering is never read as
   stopped; a 50006 link that is down means power is unknown, and nothing is toggled.
3. **Compare against what we last commanded**, never against the controller's own
   state - `_Pause` sets PAUSED ~300 ms before calling `pause()`.
4. **Power is read before it is toggled**, and our own confirmation is never mirrored
   back into LMS.
5. **Failures are bounded.** Three failed loads stop the player.
6. **Never assume an optional UPnP action exists.**
7. **Never sweep a subnet.** Multicast, a known address, and nothing else.
8. **One request for the next track per track** - at the end of stream, never at the hand-over.
